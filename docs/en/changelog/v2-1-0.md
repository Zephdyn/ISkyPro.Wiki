# 2.1.0

Release date: 2026-11-13

This is a stability release focused on ISky v1 plugin load diagnostics and timeouts. It contains no Plugin SDK interface changes, so existing plugins do not need to be rebuilt.

## ✨ New Features

- Plugins: An ISky v1 plugin load now uses its own budget (30 seconds by default) instead of sharing the 5-second message dispatch timeout. Slow first starts (antivirus scanning, slow disks) and plugins that call the network during initialization no longer fail because the window was too short.
- Plugins: A failed load now reports a readable reason naming the reached stage (not connected / plugin information not read / initialization not finished) together with the host process id and host log path; the plugin detail panel shows the same reason.
- Plugins: `isky.exe` output is written to `data/logs/pluginhost/`, so Windows-service deployments without a console can be diagnosed after the fact. The latest 5 log files per plugin are kept, each capped at 8 MB.
- Settings: The runtime section gained "Startup timeout ms" (default 30000), adjustable directly in the WebUI.

## ♻️ Compatibility

- After a load timeout the host is terminated and retried or disabled through the crash policy; it no longer stays in "starting".
- Load failures no longer show only `Plugin ... is not initialized.`; troubleshoot using the stage in the message and the host log, as described in [Plugin Troubleshooting](/en/plugins/troubleshooting).
- No Plugin SDK interface changes; the SDK version follows the application at `2.1.0`.
